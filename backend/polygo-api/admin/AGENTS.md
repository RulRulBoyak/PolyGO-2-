# PolyGo+ Admin — Unified Admin Control Center (admin folder of polygo-api)

Plain PHP admin panel for the PolyGo+ Android marketplace. Served by XAMPP Apache at `http://localhost/polygo-api/admin/`. No build system, no tests, no lint, no git repo (also true for `..`).

## The one critical thing

Every page does `require_once 'config/database.php';` then calls `getConnection()`, `requireAdmin()`, `isAdminLoggedIn()`, `csrfToken()`/`verifyCsrf()`. That file is **gitignored and not in the repo** — recreate it from `config/database.php` (PDO to the live DB; helpers: `getConnection`, `isAdminLoggedIn`, `csrfToken`, `verifyCsrf`, `requireAdmin`, `adminPassword`, `adminRateLimit`). Without it every page 500s.

## Login & modules

- Pages: `index.php` (Dashboard — live Chart.js version; its JSON source is `dashboard_json.php`), `users.php` (Community/Police), `verification.php` (Verification bridge), `listings.php` (Store), `categories.php`, `reports.php`, `pulse.php` (Cloud: announcements + feed moderation), `admin_broadcast.php` (Remote Control: live alert to all devices), `events.php` (Community: publish campus events seen in Events tab), `analytics.php` (Green Impact), `ai_chat.php` (AI Green Assistant: Gemini chat grounded in the deduplicated green metrics; uses `GEMINI_API_KEY` from `../secrets.php` — never in the browser; rate-limited via `adminRateLimit($pdo, 'ai_chat_admin', 30, 3600)`; session-held `contents[]` history capped at 40 messages; model `gemini-3.6-flash`; `ai_suggest.php` uses the same model), `maintenance.php` (System: app kill-switch), `firebase_monitor.php` (System: live Firestore pulse feed). `dashboard.php` is a redirect alias to `index.php`.
- Admin login is a **single shared password**: `hash_equals(ADMIN_PASSWORD from ../secrets.php)`, seeded via `adminPassword()`, with a `rate_limits`-backed limiter (`adminRateLimit`). Session flag is `$_SESSION['admin_auth'] = true` (checked by `isAdminLoggedIn()`). The old DB-row admin login (admin@politeknik.edu.my / admin123, user id 35) no longer authenticates.

## DB facts (hard-earned)

- The admin targets the **same `polygo` database as the API** (`../config.php`): host `127.0.0.1`, port **3306**, user `root`, empty pass. Ignore `../db.php` — it points at a stale/separate MySQL 8 instance on port **3307** (different schema, irrelevant).
- The live schema is the Android API's, **not** the admin pages' original expectations. Migrations/alts that assume `user_id`, `password`, `status`, `verified`, `listing_id`, `category_id`, `report_id` on those tables are wrong. Real columns:
  - `users`: `id`, `full_name`, `student_id`, `email`, `password_hash` (bcrypt, use `password_verify`), `role` (`'Student'`/`'admin'`), `is_verified`, `verification_status` enum(`unverified`/`pending`/`approved`/`rejected`), `verification_photo`, `fcm_token`, `is_verified`, **`is_banned`** (added by the admin panel), **`banned_at`** (set/cleared on ban/unban), `created_at`/`updated_at`. No username/institution/status columns.
  - `listings`: `id`, `owner_id` (→ `users.id`), `title`, `category` (**varchar name**, not FK), `price`, `image_url`, `is_available` (0=sold), `archived_at` (NULL=live, set=removed), `views`. No status/listing_type/category_id columns.
  - `categories`: `id`, `name` (unique), `icon_res`, `is_published`, `proposed_by`. Reference by `name` from listings.
  - `reports`: `id`, `reporter_id`, `target_type` (`'listing'`), `target_id` (listing id **as a string**), `reason`, `details`, `created_at`. Join listings via `CAST(target_id AS UNSIGNED) = l.id`.
  - `campus_alerts` (the app's "pulse" feed): `id`, `user_id` (**FK → users.id**, must be a real admin user), `user_name`, `tag` enum(`ANNOUNCEMENT`/`REQUEST`/`FLASH SALE`/`EVENT`), `title`, `body`, `status` enum(`pending`/`approved`/`hidden`), `created_at`.
  - `impact_entries`: `transaction_id`, `category_name`, `co2_kg`, `water_l`, `paper_kg`, `energy_kwh`, `created_at` → **Green Impact analytics** charts. **Each completed deal earns 2 rows (buyer + seller are both credited), so any campus-wide SUM must dedupe to one row per transaction** — `analytics.php`, `dashboard_json.php`/`index.php`, and `ai_chat.php` use `GROUP BY transaction_id` with `MAX(co2_kg)` etc. for that. The app's own leaderboard uses `ImpactEngine::leaderboard()`, which excludes `is_banned = 1` users. No `sustainability_metrics`/`pulse`/`verify` tables exist.
  - `verification_requests`: `user_id`, `verification_email`, `status` enum(`pending`/`approved`/`rejected`) — the audit log mirror of `users.verification_status`.
- **Report moderation state lives OUTSIDE the app tables** in `admin_report_actions (report_id, status ENUM('pending','resolved','dismissed'))`, auto-created by `getConnection()`. Never add admin-only columns to the app's tables (the only app-table alteration the panel made is the additive `users.is_banned`).
- Ban mechanics: users page sets `is_banned=1, banned_at=NOW()`, archives all the user's listings (`archived_at=NOW(), is_available=0`), and blocks them everywhere: `login.php`/`google_login.php` return HTTP 401 "suspended" at login; `../config.php` `verify_jwt()` re-checks `is_banned` (via `isUserBanned($pdo, $id)`, needs `global $pdo`; strict callers get 401 "suspended", optional callers get 0); `NotificationManager::sendToUser()` skips banned users (no inbox row/push); `pulse.php` announce excludes them (keeps their `fcm_token` so unban restores push without re-login). Android mirrors this with a cached `is_banned` (User model), a `BannedActivity` screen routed from Splash, and 401-body "suspended" detection in `NetworkModule`.
- Verified-seller badge on listings is **derived from owner `is_verified`** — no per-listing flag (per user decision).

## Conventions

- Page bootstrap pattern: `require_once 'config/database.php'; requireAdmin(); $pdo = getConnection();` then HTML + `includes/sidebar.php`, `includes/header.php`, `includes/footer.php`, Bootstrap 5 + Icons via CDN, dark "PolyGo Blue" theme in `assets/css/style.css`, `assets/js/main.js` (sidebar toggle, `data-confirm` confirms, auto-dismiss). Admin brand mark is `assets/logo.svg` (white-tile SVG, shown in the sidebar heading and login page).
- **All POST mutations are guarded with `verifyCsrf()`** and every form must include `<input type="hidden" name="csrf_token" value="<?php echo csrfToken(); ?>">` — forgetting the hidden field silently makes the action no-op.
- Listing "status" is computed, not stored: `removed` if `archived_at` set, else `sold` if `is_available=0`, else `active`. Admin actions map to `is_available`/`archived_at`, never to a `status` column.
- Admin user actions: verify/suspend map to `is_verified`/`verification_status`; ban maps to `is_banned` (see above).
- **Broadcast to all devices** = insert `campus_alerts` (status approved, authored by a real admin user `role='admin' AND is_banned=0`) + FCM push to every non-empty `users.fcm_token` **where `is_banned = 0`** via `NotificationManager::sendToUser()` loop + `NotificationManager::postFirestore('pulse', [...])` (Firestore REST via `../service-account.json`, OAuth2 datastore scope, pure-PHP RS256 fallback). `postFirestore()` returns `['status'=>HTTP, 'body'=>...]` — surface per-step results in the UI (banned accounts are skipped and counted). Two entry points: `pulse.php` "announce" (tag from dropdown, title required) and `admin_broadcast.php` "Remote Control" `action=broadcast` (body required, title defaults to "Live Announcement", tag selector).
- **Firestore pulse doc shape is a hard contract** with `CampusPulseActivity`'s real-time listener (`collection("pulse").orderBy("created_at", DESCENDING)` reading `tag`/`title`/`body`/`user_name`/`created_at` as integer seconds). Docs MUST carry `user_name` + integer `created_at` — an `orderBy()` query silently excludes any doc missing the ordering field (older docs written with `author`/`createdAt` string were never delivered; fixed in `pulse.php` + `admin_broadcast.php`). Keep `created_at = time()` (int), never `date('c')`. Reads use `NotificationManager::listFirestore('pulse', N)` (GET via `firestoreAccessToken`, `orderBy=created_at desc`, returns `['status'=>HTTP,'body'=>raw]`); `firestore_pulse_json.php` decodes it to `{ok,http,error,docs,fetched_at}` (tokens/keys never leave the server) and `firebase_monitor.php` polls it every 15s to render the live feed next to the `campus_alerts` mirror.
- **Maintenance kill-switch**: `maintenance.php` upserts `app_settings` keys `maintenance` ('1'/'0') + `maintenance_message`. `../status.php` reads them and returns `{maintenance:bool, maintenance_message:string}`; the Android app checks `status.php` at Splash launch, on Home resume and while retrying `ErrorStateActivity` (caches the flag via `AppDataStore.setMaintenanceMode`, then routes to the maintenance screen until the flag clears).
- Verification photos are stored as emulator-scoped absolute URLs (`http://10.0.2.2/polygo-api/uploads/...`); `verification.php`'s `adminPhotoUrl()` rewrites the origin to the current admin host.
- Dev/test: `php -l <file>` for syntax; pages can be run headlessly with `php page.php` (queries need a live MySQL on 3306; `php` is at `C:\xampp\php\php.exe`, not on PATH). CLI `$_SERVER['REQUEST_METHOD']`/`getallheaders()` are unset — set them if testing POST logic / the API JWT gate in CLI. Smoke harness lives in `%TEMP%\opencode\smoke.php`; functional POST harness `posttest.php` (disposable rows, asserts DB state, cleans up).

## Known gaps (do not "fix" silently)

- `assets/css/script.js` is an empty file; the real stylesheet is `assets/css/style.css` (copied from `assets/css/js/style.css`).
- `reports.php` only surfaces reports with `target_type='listing'`.
- Android app reads `is_banned` on the client: `login.php`/`verify.php` now return it, `User` model caches it, `SplashActivity` routes to `BannedActivity`, and `NetworkModule`'s 401 handler peeks the body for "suspended" to show the banned screen instead of a silent logout.
- Google FCM/Firestore writes need live internet + valid `../secrets.php`/`../service-account.json`; they fail softly (DB stays authoritative) when offline.
